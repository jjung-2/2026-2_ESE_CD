# 02. 교수님 피드백 반영 계획

작성: 길선영 · 2026-10-29

## 1. 교수님 피드백과 반영 내용

| 번호 | 교수님 피드백 | 우리가 하는 것 |
|---|---|---|
| F1 | 자전거 지도에 실시간 위험 요소 알림 기능이 들어가야 함 | 주행 중 위험 지점에 가까워지면 화면·음성·진동으로 경고 |
| F2 | 기존 자전거 지도 서비스를 분석해서 차별성을 둬야 함 | 국내외 서비스 비교표 작성 |
| F3 | 지도 파트와 GPS·포트홀 파트를 분리해야 함 | 감지 파트와 지도·알림 파트를 나누고, 서버 API로만 주고받음 |
| F4 | depth 카메라 대신 2D로 전환, 일반 스마트폰 카메라로 위험 요소 확인·알림 | 핸들에 거치한 스마트폰 카메라로 포트홀·장애물을 인식하는 AI 기능 |
| F5 | 파트를 잘 나눠서 하기 | 팀원별 담당 파트와 완료 기준을 정함 |

**지난 계획에서 바뀐 점**

- depth 카메라 실험을 빼고, 스마트폰 카메라(2D) 인식으로 바꿨다. 추가 장비 없이 누구나 쓸 수 있다.
- 라즈베리파이 같은 소형 컴퓨터는 쓰지 않는다. 영상 처리는 스마트폰이 맡는다.
- 주변 위험 알림을 "확장"에서 "필수"로 올렸다.

## 2. 기존 자전거 지도 서비스 분석 (F2)

공개 자료 기준으로 정리했다. 일부 자료는 오래되어 최신 버전은 앱을 직접 설치해 다시 확인할 필요가 있다.

| 서비스 | 주요 기능 | 위험 정보 처리 방식 | 부족한 점 |
|---|---|---|---|
| [카카오맵 자전거 길찾기](https://www.inews24.com/view/1047915) | 자전거도로 우선, 최단 거리, 편안한 길 경로 | 경사·계단을 피하는 경로 옵션 | 포트홀 같은 노면 위험 정보와 경고가 없음 |
| [네이버 지도 자전거 길찾기](https://www.venturesquare.net/274/) | 자전거 전용도로 위주 안내 | 위험 도로를 경로에서 제외 | 노면 상태 정보와 이용자 제보가 없음 |
| [오픈라이더 (서울시 연계)](https://news.seoul.go.kr/traffic/archives/504054) | 자전거길 안내, 주행 기록 | 사진 제안 등록, 공감 20개 이상이면 서울시에 접수 | 정책 건의용이라 주행 중 알림이 없음 |
| [모토맵 (RideMap)](https://mwm.ai/apps/ridemap/6773636183) | 라이더용 장소·코스 추천 | 장소·위험 사용자 제보 | 노면 정보와 자동 감지가 없음 |
| [Bikemap (해외)](https://help.bikemap.net/hc/en-us/articles/360017455679) | 자전거 내비게이션, 커뮤니티 제보 | 위험·장애물 제보, 투표로 신뢰도, 유형별 만료 | 사람이 직접 올려야만 쌓임 |
| [BikeMaps.org (해외)](https://amp.cbc.ca/news/canada/newfoundland-labrador/bike-maps-app-cycling-safety-1.4137811) | 사고·아차 사고·위험 제보 지도 | 도시 계획용 데이터로 활용 | 이용자 알림 기능은 확인되지 않음 |
| [서울시 포트홀 신고](https://news.seoul.go.kr/safe/archives/512809) | 120 전화, 웹, 앱 신고 | 담당 부서가 보수 | 신고 내용이 다른 이용자에게 공유되지 않음 |

**분석 기준:** 위험 정보가 어떻게 모이는지(사람 제보 / 자동 감지), 주행 중인 사람에게 알려 주는지, 오래되거나 틀린 정보를 거르는 장치가 있는지.

**결론:** 확인한 서비스는 대부분 "사람이 제보하고 지도에 표시"하는 방식이었다. 교수님이 제안하신 **실시간 위험 알림**과 **카메라 자동 인식**은 확인한 서비스에 없는 기능이다.

**우리 서비스의 차별점**

1. **자동으로 쌓인다.** 단말의 충격 감지와 스마트폰 카메라가 주행만 해도 위험을 찾는다.
2. **주행 중에 실시간으로 알려 준다.** 진행 방향 앞에 있는 위험만, 속도에 맞춘 거리에서, 음성과 진동으로 알린다.
3. **여러 근거를 합쳐 신뢰도를 관리한다.** 충격, 카메라, 사람 제보를 한 지점으로 묶어 신뢰도를 계산하고, 오래된 정보는 만료한다.

> 주의: 자동 감지 자체는 연구로 많이 다뤄졌다(Pothole Patrol 등). 차별점은 "자동 감지와 제보를 합쳐 자전거 이용자에게 실시간으로 알려 주는 서비스"라는 조합에 있다.

## 3. 파트 분리 구조 (F3)

| 파트 | 구성 요소 | 하는 일 | 내보내는 것 |
|---|---|---|---|
| 감지 | 센서 단말 (ESP32-S3, IMU, GPS, microSD) | 충격 기록, 충격 이벤트 검출 | 충격 이벤트 |
| 감지 | 스마트폰 카메라 AI | 전방 위험 인식 | 카메라 이벤트 + 노면 사진 |
| 지도·알림 | 서버·DB (FastAPI) | 저장, 같은 지점 통합, 신뢰도·상태 관리 | 위험 지점 목록 |
| 지도·알림 | 앱 | 위험 지도, 제보, 주행 중 알림 | 사용자 제보, 확인 응답 |

두 파트는 정해진 데이터 형식(API)으로만 주고받으므로, 한쪽이 늦어져도 다른 쪽은 가짜 데이터로 개발할 수 있다.

## 4. 실시간 위험 알림 설계 (F1)

알림은 단말 없이 스마트폰만으로 동작하게 한다. 단말이 없는 일반 이용자도 알림을 받을 수 있다.

1. **내 위치 확인:** 스마트폰 위치를 1초마다 받아 이동 방향과 속도를 계산한다.
2. **주변 위험 받기:** 반경 1km 안의 위험 지점을 서버에서 받아 폰에 저장한다. 30초마다 또는 300m 이동마다 새로 받는다.
3. **앞에 있는 위험만 고르기:** 진행 방향 앞쪽의 위험만 남긴다. 지나친 위험이나 옆길 위험은 알리지 않는다.
4. **2단계 알림:** 100m 앞에서 음성 예고, 도착 약 5초 전(최소 30m)에 진동·경고음.
5. **반복 알림 막기:** 한 번 알린 지점은 5분 동안 다시 알리지 않는다.
6. **지나간 뒤 확인:** 멈췄을 때나 주행이 끝났을 때 "아직 있어요 / 없어졌어요"를 받아 신뢰도에 반영한다.

| 방식 | 구현 | 비고 |
|---|---|---|
| 화면 | 지도 위 경고 배너, 유형별 아이콘 | 크게 표시 |
| 음성 | TTS | 짧게 |
| 진동 | 진동 기능 | |
| 화면 켜짐 유지 | Wake Lock | 주행 중 화면이 꺼지지 않게 |

수치(100m, 5초, 5분)는 초깃값이며 시험 주행에서 조정한다.

**검토 메모:** 진행 방향 ±45도 기준은 100m 앞에서 옆으로 약 70m까지 포함해 옆길 위험에도 알림이 울릴 수 있다. "앞쪽 거리 100m 이내, 옆쪽 거리 15~25m 이내" 기준을 시뮬레이션으로 비교해 볼 필요가 있다.

## 5. 스마트폰 카메라(2D) 위험 인식 (F4)

| 클래스 | 예시 | 학습 데이터 |
|---|---|---|
| 포트홀 | 패인 구멍 | 공개 데이터 + 직접 촬영 |
| 노면 파손 | 거북등 균열, 큰 균열 | 공개 데이터 + 직접 촬영 |
| 물 고임 | 비 온 뒤 웅덩이 | 직접 촬영 |
| 장애물·공사 | 라바콘, 공사 표지판 | 직접 촬영 |

**만드는 순서**

1. 공개 데이터로 1차 학습: [RDD2022](https://arxiv.org/pdf/2209.08538)(6개국 도로 사진 47,420장)와 공개 포트홀 데이터셋으로 YOLOv8n을 학습한다.
2. 자전거도로 영상으로 2차 학습: 공개 데이터는 자동차 시점이므로, 핸들 거치 폰으로 찍은 영상에서 사진을 뽑아 추가 학습한다.
3. 폰에 올리기: 스마트폰용 형식(TFLite)으로 변환한다.
4. 오탐 줄이기: 연속 3프레임 이상, 신뢰도 0.5 이상일 때만 위험으로 판정하고 화면 위쪽(하늘·건물)은 무시한다.
5. 알리고 올리기: 음성으로 즉시 알리고, 노면 부분만 잘라낸 사진과 위치를 서버에 올린다.

**주의할 점:** 개인정보(얼굴·번호판)를 피하기 위해 노면 부분만 잘라 올린다. 야간·비·역광에서는 성능이 떨어지므로 낮과 맑은 날을 기본으로 평가하고 다른 환경은 한계로 밝힌다.

## 6. 평가 지표

| 항목 | 측정 방법 | 목표 (초깃값) |
|---|---|---|
| 충격 감지 | 라벨 구간 대비 정밀도·재현율·F1 | F1 0.8 이상 |
| 카메라 인식 | 자전거도로 시험 영상의 정밀도·재현율 | 각 0.7 이상 |
| 카메라 속도 | 폰에서 초당 처리 장수 | 5장 이상 |
| 위치 정확도 | 실제 위치와 지도 위치의 거리 | 10m 이내 |
| 실시간 알림 | 도착 전 알림 성공률 | 90% 이상, 도착 3초 전 이상 |
| 기록 안정성 | 1시간 연속 기록 누락 여부 | 누락 없음 |

## 7. 교수님께 확인할 사항

- "depth를 2D로 전환"이 일반 카메라로 위험 요소를 인식하는 것까지인지, 2D 영상에서 깊이를 추정하는 것(예: 단일 영상 깊이 추정 모델)까지 포함하는지.
- "바이크맵"이 특정 앱을 말씀하신 것인지, 자전거 지도 서비스 전반을 말씀하신 것인지.
