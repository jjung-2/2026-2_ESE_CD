# 06. 단계별 개발 계획 (초기안)

작성: 길선영 · 2026-10-29

레퍼런스(RoadQuality GPSTracker 등) 구조를 따라 업그레이드 부품으로 기본 장치를 먼저 완성하고, 그 위에 교수님 피드백 기능(실시간 알림, 스마트폰 카메라 인식)을 하나씩 추가하는 방식으로 세운 초기 계획이다. 이후 실제 진행 상황에 맞춰 [07 소프트웨어 개발 계획](07_소프트웨어_개발_계획.md)과 [08 전체 개발 계획](08_전체_개발_계획.md)으로 구체화했다.

## 1. 진행 원칙

1. **한 번에 하나씩:** 부품도 기능도 하나씩 연결하고, 동작을 확인한 뒤 다음으로 넘어간다.
2. **레퍼런스 먼저, 업그레이드는 나중에:** 처음에는 레퍼런스 구조를 그대로 따라 하고, 기본 장치가 동작한 뒤 우리 기능을 붙인다.
3. **기다리지 않기:** 부품이 오기 전에도 소프트웨어 담당은 각자 할 일을 시작한다.
4. **AI는 도구로 쓰기:** 코드는 AI로 만들되, 각자 맡은 부분은 직접 설명할 수 있을 만큼 이해한다.
5. **매주 확인:** 매주 한 번 모여 각자 만든 것을 직접 실행해 보여 준다.

## 2. 단계

| 단계 | 시기 | 목표 | 완료 확인 |
|---|---|---|---|
| 0단계 | 1주차 | 부품 주문, 개발 환경 설치, GitHub 저장소 준비 | 부품 주문 완료, 전원 "Hello World" 실행 |
| 1단계 | 1~2주차 | 부품 도착 전 각자 가장 작은 예제 성공 (배선도, 진동 그래프, YOLO 예제, 간단한 서버, 지도 앱) | 각자 결과물 1개 |
| 2단계 | 2~3주차 | 부품을 하나씩 ESP32에 연결 (ESP32 → IMU → GPS → microSD → 버튼 → 배터리) | 부품별 단독 동작 확인 |
| 3단계 | 3~4주차 | 기본 장치 완성, 자전거 장착, 10분 첫 주행 (레퍼런스 수준) | 끊김 없는 기록, 요철에서 충격 확인 |
| 4단계 | 5~7주차 | 반복 주행 데이터 수집, 충격 감지 규칙, 카메라 2차 학습, 서버·앱 기본 기능 | 감지 규칙 초안, 지도 표시 |
| 5단계 | 8~9주차 | 기능 추가 1: 감지 결과를 지도에 올리기 | 요철 통과 후 1분 안에 지도 표시 |
| 6단계 | 9~10주차 | 기능 추가 2: 실시간 위험 알림 (교수님 피드백) | 가짜 위험 10개 중 9개 이상 도착 전 알림 |
| 7단계 | 10~12주차 | 기능 추가 3: 스마트폰 카메라 위험 인식 (교수님 피드백) | 정밀도·재현율 0.7 이상, 초당 5장 이상 |
| 8단계 | 13~15주차 | 통합 시험과 평가 | 평가 지표 표 정리 |
| 9단계 | 16주차 | 발표 준비 | 시연 영상 |

## 3. 부품 연결 순서와 자주 하는 실수

| 순서 | 연결 | 확인 방법 | 자주 하는 실수 |
|---|---|---|---|
| ① | ESP32만 USB로 연결 | 시리얼 모니터에 글자 출력 | 충전 전용 케이블 사용, 드라이버 미설치 |
| ② | ESP32 + IMU | 가만히 두면 한 축이 약 9.8, 흔들면 값이 변함 | 5V 연결, CS 핀 미연결 |
| ③ | ESP32 + GPS | 실외에서 위도·경도·속도 출력 | 실내 테스트, TX와 RX 반대 연결 |
| ④ | ESP32 + microSD | 파일에 한 줄 저장 후 PC에서 확인 | 카드 포맷(FAT32) 안 함 |
| ⑤ | ESP32 + 버튼 | 누를 때마다 출력 | 풀업 설정 안 함 |
| ⑥ | 배터리로 전원 공급 | USB 없이 동작 | 배터리 방향 반대 |

## 4. 막혔을 때 확인 순서

1. 전원과 배선을 다시 본다.
2. 마지막으로 바꾼 것 하나만 되돌려 본다.
3. 부품을 하나만 남기고 따로 시험한다.
4. 오류 메시지를 그대로 AI에게 묻는다.
5. 하루 이상 막히면 팀 회의에서 공유한다.
